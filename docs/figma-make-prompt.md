# Figma Make 用デザインプロンプト

Figma Make に貼り付けるプロンプト。生成結果は SPEC.md §5.2 の視覚的リファレンス（正）となる。

---

## プロンプト本文

```
macOS向けデスクトップアプリ「diffwww」のUIをデザインしてください。
ファイル差分を「見る」ことに特化した閲覧専用の比較ツールです（編集機能は一切ありません）。
WinMergeの分かりやすさを、モダンな開発者向けツールのデザインで再構成するイメージです。
実装は React + Tailwind CSS + shadcn/ui を想定しています。

## デザインの方向性

- ダークテーマ基調。VS CodeやGitHub Darkのようなコードエディタ風の落ち着いた配色
- 背景は濃いチャコール（#1a1d23前後）、パネルやカードは一段明るいグレー（#23272e前後）、境界線は控えめな #333 系
- アクセントカラーはティール/シアン系（#2dd4bf 前後）を1色だけ。プライマリボタン・選択状態・フォーカスリングのみに使う
- グラデーション・派手なシャドウ・装飾アニメーションは使わない。フラットで実用的
- コード・ファイルパス・行番号・ハッシュ値はすべて等幅フォント（JetBrains Mono系）。UIラベルはサンセリフ
- 情報密度は高め。余白は詰め気味、角丸は4〜6pxの控えめなもの
- デスクトップアプリなのでウィンドウ幅1280px以上を想定

## 画面レイアウト

### ヘッダー（上部固定）
- 左端にアプリ名「diffwww」とシンプルなロゴ
- モード切替タブ:「フォルダ比較」「git比較」の2つ
- フォルダ比較モード: 左フォルダパス入力欄、右フォルダパス入力欄（各欄にフォルダ選択ボタン付き）、「比較」プライマリボタン
- git比較モード: リポジトリパス入力欄1つ + その下にA/B 2組のセレクター（各組: ブランチのドロップダウン + コミットのドロップダウン。コミットは「短縮ハッシュ7桁 + コミットメッセージ + 日付」を等幅フォントで表示）
- 検索ボックス（ファイル名絞り込み）とステータスフィルタのドロップダウン（すべて/追加/削除/変更/同一）
- 統計バッジ: +12（緑）/ -5（赤）/ ~8（黄）/ =120（グレー）のようなコンパクトなピル型バッジ
- 比較実行中に表示する細いプログレスバー

### メインエリア（左右2ペイン）
- 左ペイン（幅約380px）: ファイルツリー
  - フォルダは開閉可能、インデントで階層表現
  - 各行の左端にステータス色のボーダー（追加=緑、削除=赤、変更=黄、同一=グレー）と行背景の淡い色付け
  - 選択中のファイルはアクセントカラーでハイライト
- 右ペイン（残り全幅）: 差分詳細ビュー
  - 上部にファイルパスとステータスバッジを表示する薄いバー
  - テキストファイル: 左右2カラムのSplit Diff
    - 各カラムに行番号ガター（背景を一段濃くし、水平スクロールしても左に固定）
    - 追加行は緑系の背景（ダークテーマに合う低彩度・半透明）、削除行は赤系の背景、変更なしは透明
    - 【重要】長い行は折り返さない。各カラムに水平スクロールバーを表示し、はみ出た行はスクロールして読める。行の背景色はスクロール領域の全幅まで続く
    - 水平スクロールバーは目立ちすぎない濃いグレーで、overflow時に常時表示
  - バイナリファイル: ファイルサイズ・ハッシュ値・更新日時をカード型で表示

## 作成してほしい画面（3枚）

1. フォルダ比較モード: 比較結果表示中。ツリーに追加/削除/変更/同一が混在し、変更されたテキストファイルを選択してSplit Diffが表示されている状態。右カラムに横に長いコード行があり、水平スクロールバーが見えている状態を含めること
2. git比較モード: リポジトリ選択済みで、A=mainブランチ、B=featureブランチのコミットを選択し、変更ファイルツリーとSplit Diffが表示されている状態
3. 空状態（初回起動時）: パス未入力で、中央に「フォルダまたはgitリポジトリをドラッグ＆ドロップ」という控えめな案内が表示されている状態
```

## 運用メモ

- 生成結果が SPEC.md と食い違う場合は SPEC.md を優先し、必要ならデザインを再生成する
- 生成されたコード（React + Tailwind）の `types.ts` / `mockData.ts` 相当は、issue分割時にモックファースト開発の起点として利用する
- 長い行の水平スクロール表現（画面1）は Peekdiff の既知問題への対策なので、生成結果に含まれているか必ず確認する
